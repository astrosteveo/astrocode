# astrocode

Our own version of `claude`: a terminal front end (Ink 8, React 19, Bun) for Claude Code, built on the Claude Agent SDK (`@anthropic-ai/claude-agent-sdk`). The web front end was removed on 2026-10-15; it's in commit 623882d if it's ever needed.

## Layout

- `src/cli.ts`: the `astrocode` command
- `src/session.ts`: the Agent SDK session
- `src/events.ts`: what the session tells the interface
- `src/history.ts`: saved sessions and replayed conversations
- `src/plugins.ts`: plugins and marketplaces, through `claude plugin … --json`
- `src/settings.ts`: what astrocode remembers between sessions; `src/stash.ts`: the Ctrl+S stash, per project
- `src/shell.ts` runs `!` commands in a pty; `src/memory.ts` adds `#` notes to a CLAUDE.md
- `src/view/`: the reducer (`state.ts`), the to-do list (`todos.ts`), runs of tool calls folded into one row (`folds.ts`), tool summaries, shell commands as cards read them and what runs alongside the conversation (`runs.ts`), a terminal's output as lines (`terminal.ts`), permission wording and formatting
- `tui/`: the Ink components. `app.tsx` lays them out in scrollback (the default) or full screen (`screen.tsx`). `config.tsx` is `/config`, `model-picker.tsx` is Alt+P and `/model`, and `effort.tsx` the `◀ value ▶` dial they share. `keys.ts` is the message box's keymap. `plugins.tsx` is `/plugins`; `files.ts` lists files for the message box's `@` menu, `arguments.ts` a command's choices for its first argument, `images.ts` reads pasted images, `pictures.tsx` draws them in the transcript in kitty, and `editor.ts` opens `$EDITOR` for Ctrl+G. `shell-card.tsx` draws shell commands; `tasks.tsx` is the view of one thing running. `links.ts` makes web addresses into links and opens them.
- `tui/diff.tsx`: edits as diffs, unified or side by side; `tui/find.tsx`: full screen's Ctrl+F; `tui/session-preview.tsx`: the end of a saved session, under /resume's list
- `tui/cache.ts`: how long the prompt cache stays warm, and keeping it warm while you're away
- `tui/window.ts` and `tui/attention.ts`: the terminal window around astrocode (focus, title, the tab's progress, notifications) and what the conversation tells it
- `tui/transcript.tsx`, `tui/mouse.ts`, `tui/selection.ts`, `tui/clipboard.ts`: full screen's transcript as lines, the mouse, and copying

## Commands

- `bun src/cli.ts [dir]`, or `bun src/cli.ts -f [dir]` for full screen. Use `ASTROCODE_MODEL=haiku` for cheap test runs.
- `bun run typecheck`

## Rules

- Take SDK types from `node_modules/@anthropic-ai/claude-agent-sdk/sdk.d.ts` and `sdk-tools.d.ts` (tool inputs and outputs), and Ink's API from `node_modules/ink/readme.md`. Don't guess them.
- Keep `permissionMode` explicit in `src/session.ts`. Without it, Claude Code starts in the mode from the user's settings (`bypassPermissions` here), and no permission prompt ever shows. astrocode starts in the mode last picked in astrocode, else `auto`, Claude Code's own default when nothing is set, whose classifier asks through `canUseTool` when it can't decide. Where auto isn't available, Claude Code starts in `default` instead and says so in `initializationResult()`'s `current_permission_mode`, which isn't in the SDK's types.
- The model, effort, mode, layout (full screen or not), notifications, when plan usage shows and keep-warm the user picks are remembered in astrocode's own `$XDG_CONFIG_HOME/astrocode/settings.json` (`~/.config/…`), not in Claude Code's settings, so `claude` keeps its own. Plan mode and `max` effort are for one session only, as in Claude Code, and so are `-m`, `-e`, `-f`/`--no-fullscreen` and their env vars. `/fullscreen` and `/config fullscreen=…` are picks. `tui/main.tsx` waits for pending saves before exiting. A mode Claude Code switches to by itself, such as on leaving plan mode, isn't a pick.
- "Always allow" applies only `narrowest()` of Claude Code's suggestions. The full list can include `setMode: acceptEdits`, which silently turns off every later edit prompt. The option's label comes from `alwaysLabel()`.
- AskUserQuestion arrives through `canUseTool`, even in bypass mode, and is answered with `updatedInput: { ...input, answers }`. Answers are keyed by question text, and a multi-select answer joins its labels with ", ".
- `src/view/state.ts` must stay a pure reducer. A resumed conversation is replayed through it as one `history` event.
- Saved transcripts have no record of permission prompts, so a refused tool is recognized by Claude Code's "The user doesn't want to proceed" result.
- Effort is set with `applyFlagSettings({ effortLevel })` mid-session and the `effort` option at start. Claude Code doesn't report its default effort to the SDK, so the status bar shows only a level astrocode set.
- The status bar's `cache 54m` is how long the conversation's prompt cache stays warm: from the last main-thread message Claude sent (`at`, live or the saved timestamp in a replay; not a subagent's, nor Claude Code's `<synthetic>` errors), for the TTL its usage says it wrote (`cache_creation.ephemeral_1h_input_tokens` or `_5m_`), else the last known, else an hour, Claude Code's default on a subscription within its limits. Keep-warm (`/config`, or a click on the reading; off unless picked) sends `AgentSession.warm()` while Claude isn't working, a fifth of the TTL and at most 5 minutes before expiry, for up to 8 hours after Claude last answered: one short request on the conversation forked with `persistSession: false`, so nothing is saved, with the same options as the session (`shared()`), since any difference in model, effort, thinking, tools or system prompt misses the cache and writes the whole conversation instead. A warm request that read less than it wrote missed, and turns keep-warm off. A cache already cold, as after the computer slept, isn't warmed. The keep-warm process starts as any Claude Code session does, hooks and MCP servers included.
- Rate-limit windows come from `rate_limit_info.unifiedWindows`, which isn't in the SDK's types. Read it with `field()`.
- Only finished entries go into Ink's `<Static>`, because Static never redraws. A tool row is finished once it isn't running and isn't waiting on the user, and a `!` command once it ended or went to the background (`settledCount`). `/clear` and `/resume` clear the screen and bump the store's epoch to start Static over.
- Nothing may write to the terminal behind Ink's back, or the layout shifts and leaves ghost copies of the prompt. Claude Code's stderr is dropped, and process warnings become notices (`tui/main.tsx`). The SDK's warning that canUseTool won't run in bypass mode is dropped, because questions still come through it.
- Raw mode goes on before each `render()` (`tui/main.tsx`). Ink asks the terminal about the kitty keyboard protocol as it starts, before its input hooks turn raw mode on, and a terminal still echoing prints the answer as `^[[?0u`. tmux doesn't answer that query, so tmux tests can't show this; kitty does.
- The message box's keys are actions with Claude Code's names and defaults (`DEFAULTS` in `tui/keys.ts`, from the binary's `"ctrl+s":"chat:stash"` table; check it when Claude Code updates), with the user's `~/.claude/keybindings.json` (`$CLAUDE_CONFIG_DIR`) over them, so one file rebinds both. Only Claude Code's action names go in that file: an astrocode-only name would be flagged by `claude`. Esc, the arrows, Ctrl+Z and the shell's editing keys (Ctrl+A/E/K/U/W/Y, Alt+B/F/D) aren't actions and stay built in, after the keymap. Ctrl+S differs on purpose: Claude Code puts a stash back after the next send, astrocode keeps it until Ctrl+S, in the `Store` and on disk with its images, renumbered on the next start. Sending or stashing starts the undo history over.
- A message sent while Claude works (`busy`) goes to Claude Code at once, which queues it and folds it into the turn between tool rounds or runs it after. Until then it's in `state.queue`, drawn above the box (`tui/queued.tsx`), not in the transcript: Claude Code's `command_lifecycle` messages (not in the SDK's types; `command_uuid` is the message's `uuid`) say `started` when Claude takes it, which moves it to the end of the transcript, where Claude read it, and `cancelled` when it's taken back. ↑ in an empty box takes the queue back with `cancelAsyncMessage(uuid)` (`unqueue()`; in the SDK's code, not Query's type), which is false once Claude has started on it, and puts the texts in the box, joined. A replay has no results, so `busy` is cleared before each replayed prompt and nothing in it queues.
- Send now (Ctrl+Enter, Ctrl+X Ctrl+S) interrupts, waits for the stopped turn to close, then sends; sending before the close puts the old turn's last words after the new message.
- Thinking is turned off with `setMaxThinkingTokens(0)`, or `thinking: { type: "disabled" }` at start, and back on with null, or a budget when Claude Code started without it. Current models report `supportsThinkingOff: false` (not in the SDK's types; read with `field()`) and think regardless, so Alt+T and `/config` say so instead of pretending.
- Ctrl+Z raises SIGTSTP on astrocode only, inside `suspendTerminal()`. Without job control the kernel drops it, and astrocode says so.
- `/config` with no arguments is astrocode's own menu, and changes nothing until it closes: Esc applies what changed (model before effort, layout last) and writes it in one `remember()`; Ctrl+C discards. `/config key=value` still goes to Claude Code, except `fullscreen=`.
- The message box keeps its text in a ref, because keys can arrive faster than React re-renders. So does `/plugins` with where you are in it: two quick ↓ then Enter must act on the row they reached.
- The SDK can only load and reload plugins. Installing, removing and turning them on or off run Claude Code's own `claude plugin … --json` with the binary the SDK ships (`claudeBinary()`), and then `reloadPlugins()` refreshes the session and the `/` menu. `claude plugin enable` and `disable` accept any id, installed or not, and write it into settings, so offer them only for installed plugins. Never pass `-y`: a plugin that installs by running a command must be confirmed by a person in `claude` itself.
- The message box's menu (commands, their arguments, `@` files) unfolds up out of the box and folds back into it, so the box never moves. It's drawn absolutely, its bottom on the box's top edge (`bottom="100%"`), and in full screen covers the transcript. Scrollback can't draw above Ink's live part, so the menu gets rows of its own there; Ink redraws the live part from its top row, so those rows stay until the message is sent, or the box would jump up. A picker or prompt that takes the keys replaces the menu at once.
- A `/` that starts a later word, as an `@` does, offers commands to write into the message (`commandAt()`): Tab or Enter writes `/name ` in, never runs it, and Claude Code passes it to Claude as text. Only names that start with what's typed, so a path like `/usr/lib` closes the menu quickly; never in `!` or `#` mode.
- The `/` menu's choices for a command's first argument come from its `argumentHint` (`[low|high]`, `[on|off]`), since the SDK doesn't pass along Claude Code's own completers. A command whose hint doesn't list them, like `/claude-api`, gets them from `KNOWN` in `tui/arguments.ts`; check that list against the binary when Claude Code updates. Enter right after `/name ` sends the command bare unless the arrows moved to a choice.
- `@path` mentions need nothing from astrocode but the menu: Claude Code expands them when the message arrives, quoted (`@"a b.md"`) when the path has a space. Don't send messages with `client_composed`, which turns that off.
- Images go with a message as image blocks before its text, each once, in the order the text first mentions them. The box shows each as `[Image #n]`; the images themselves live in the `Store`, by number, and go with any message that still mentions them. Ctrl+V reads the clipboard with `wl-paste` or `xclip`; a paste that's nothing but an image file's path, as dropping a file pastes, attaches the file.
- In kitty (`TERM=xterm-kitty`, not under tmux or screen), a sent message draws each image under the line with its first `[Image #n]` (`pictures.tsx`), and a tool call draws the images its result carried, such as a picture Claude read, under its row and in its whole output, in place of `[image]`. Each is as large as fits in the transcript's width and half the transcript's height (`pictureRows()`), keeping its shape and no larger than the image. The shape needs the cell's size in pixels, which kitty puts in the window size (`TIOCGWINSZ`, read with `bun:ffi` on Linux, again after a resize); asking with `CSI 16 t` would put the answer in Ink's stdin, and elsewhere it's guessed. kitty fits an image into its cells without stretching it, so a wrong size shows as blank rows or columns around the picture. It uses kitty's Unicode placeholders: the image goes to the terminal as PNG made by `Bun.Image`, at most 2048 pixels on a side, with one virtual placement (placement id 1, placed again when its size changes), and is drawn wherever cells of U+10EEEE with its id as the foreground color are printed; the first cell of each row carries diacritics for row and column, and kitty counts on from there. Ink garbles an underline color, so a placement id can't go in the cells. Ink lays the cells out as text, so pictures work in `<Static>` and in full screen's lines. Scrollback draws an entry once, at the size of the moment, so an image is made ready (`prepare()`) before its label goes in the box, and the `Store` holds an event that brings images not ready yet, and every event after it, until they are (`whenReady()`). The `prompt` event and item carry a message's images by label number, and a replay gets them back from the saved image blocks. A tool result's images are read out of Claude Code's message once, by `sdkEvent()`, onto the `sdk` event and from there the tool call, live and replayed alike, since a picture is kept per image object. Drawing a picture asks for it (`want()`), and so does full screen's layout for every entry with images, since it reuses lines drawn before; `afterFrame()`, Ink's `onRender`, sends what the frame asked for. kitty keeps the alternate screen's images apart and drops them on entering it, so each layout starts over (`forgetSent()`) and full screen sends them again after Ctrl+G or Ctrl+Z. kitty can leave a picture blank when it draws placeholders for an image it already has, until its next redraw, and with Ink's cursor hidden that can be a long wait; so 100 ms after a frame that drew pictures in new places, astrocode places one again, which makes kitty look again; sent along with the frame, it doesn't help. A selection passes over picture rows. An image `Bun.Image` can't read stays its label.
- Every message is sent with its own `uuid`, which Claude Code keeps as the transcript entry's. Rewinding goes back to it: `rewindFiles(uuid)` for the files (`enableFileCheckpointing` is on; only Edit and Write are tracked, not Bash), and a restart with `resumeSessionAt` set to the entry before it for the conversation. Only a dry run lists the files a rewind changes, so the picker asks for one first.
- `!` commands and `#` notes reach Claude through `note()`: a user message with `shouldQuery: false`, which goes with the next message. A `!` command is saved as Claude Code saves its own, `<bash-input>` then `<bash-stdout>`/`<bash-stderr>`, and replayed from that. Neither saves the exit code. stderr isn't failure (git prints its progress there), so a command's output is drawn as failed only when it exited non-zero, or, replayed, when Claude Code wrote `Command failed:` for one that couldn't run; the same goes for Claude's Bash calls, by their status. Claude Code answers each such message with a result of no turns; the reducer ignores those while not busy.
- A `!` command runs in a pty (`Bun.spawn` with `terminal`), so it colors its output and draws progress, with an end-of-file written first, so a prompt fails at once instead of waiting forever. Its two streams are one. What the terminal shows (`TerminalText`, which plays back carriage returns, erasing and cursor moves) streams in as `shell-output` events, at most every 100 ms and every second regardless, for the card's clock. It doesn't block: Esc and Ctrl+C stop Claude, never a command. A command stops only from its task view (`x` or Stop), Ctrl+X Ctrl+K pressed twice, /clear or a resume, or astrocode exiting; stopping sends SIGINT to its process group, then SIGTERM, then SIGKILL. Its card stays live while it's the newest entry; once anything comes after it, `add()` marks it `background`, so scrollback can write the card, and how it ended comes as a notice. The running ones' controllers live in the `Store`, so they survive `/fullscreen`. Claude gets the end of the output, at most 30,000 characters, once it ends; one you stopped says "Stopped by the user." in `<bash-stderr>`, which a replay reads as stopped.
- Claude Code sends `system/init` before every input, not once. Per-process state, such as the background tasks, resets on `ready`.
- Ctrl+B asks `backgroundTasks()` about each running tool call by id. Asked about none in particular it says yes even when nothing moved, and a command can only move once it has run for a moment. What runs in the background comes from `background_tasks_changed`, which replaces the whole set. `taskInfo` keeps what `task_started`, `task_progress` and `task_notification` say about each task of the process, ended ones too.
- /tasks, the status bar's running count and a click on something running all open it, never stop it: the list (`runningList()`) has your running `!` commands and Claude Code's background tasks, then the ended ones. The task view (`tui/tasks.tsx`) reads a background command's or Monitor's output with `getTaskOutput()`, which is in the SDK's code but not in Query's type, every second while it runs and once after it ends; a subagent shows its progress instead. Only `x` or a click on Stop stops it. Ctrl+X Ctrl+K asks first and stops everything on a second press, as Claude Code does, with no summary notice of its own: each thing stopped says how it ended.
- The pinned to-do list is folded from TaskCreate, TaskUpdate and TaskList (TodoWrite in older Claude Code). Claude Code leaves those tools out for current models unless `CLAUDE_CODE_ENABLE_TODO_TOOLS` is set, and `claude` does too; astrocode doesn't set it.
- Ctrl+G hands the terminal to the editor with Ink's `suspendTerminal()`, which puts raw mode, the kitty protocol and the alternate screen back afterwards. The mouse isn't Ink's, so it's stopped and started around it.
- The permission and question prompts ignore Enter, Space and digits for `GRACE_MS` after they appear. Don't remove that. Scripted tests must wait longer than that before pressing keys.
- Full screen (`-f`, `ASTROCODE_FULLSCREEN=1`, `/fullscreen`, `/config fullscreen=true|false`) runs in Ink's alternate screen. `/fullscreen` unmounts Ink and renders again in the other layout, so whatever must survive the switch, such as the sent-message history, lives in the `Store`, not in component state.
- Full screen draws the transcript as lines with Ink's `renderToString`, kept per item object; the reducer replaces items rather than changing them. `renderToString` shares Ink's reconciler, so it can't run during a render or a commit: `useTranscript` draws in a microtask after the commit. Anything drawn there can't use hooks.
- The terminal window hears from astrocode in both layouts (`TerminalWindow`, made once in `tui/main.tsx`). Focus reports (1004) are lifted out of `stdin.read()` like the mouse's, which wraps them in full screen. The title (OSC 2, the terminal's own pushed and popped with XTWINOPS 22/23) is a mark, `●` waiting on you or `◇` working, then Claude Code's session title, the folder and the branch. The tab's progress (OSC 9;4) goes only to terminals known to draw it, since one that reads OSC 9 as a notification would show it. A turn that ends, a prompt that opens and a `!` command of 10 s or more that ends notify while the window is out of focus; where focus is unknown, only turns of 30 s or more do. Notifications are kitty's OSC 99 (which kitty also holds back while focused; each with an id of its own, since kitty replaces a notification whose id comes again and KDE files a replacement in its history without showing it), OSC 777 for Ghostty, WezTerm and foot, OSC 9 for iTerm2 and Windows Terminal, and the bell elsewhere or when `/config` says bell; under tmux they go through its passthrough. All of it stops around Ctrl+G and Ctrl+Z and on exit. A detached tmux has no client, so it sends no focus reports; test with `send-keys -H 1b 5b 4f` (focus out) and `#{window_bell_flag}`. `ASTROCODE_TRACE=<file>` logs focus reports, each turn's end with the focus it saw, and every notification sent (`trace()`).
- In scrollback, each of your messages starts with OSC 133's marks (A, then C so the terminal still sees a command running), for the terminal's jump to the previous or next prompt. Ink's output keeps no escape code but OSC 8 links, so the message's dot is a link to `astrocode:prompt` (`PROMPT_LINK`), which `markPrompts()` swaps for the marks as Ink writes. Only the `<Static>` entries carry it; full screen's lines must not, since `linkAt()` would take it for a link. tmux's copy mode `previous-prompt` tests it.
- Full screen finds text with Ctrl+F (`tui/find.tsx`, the `find` overlay): smart case, within a row, matches drawn in the transcript by `markMatches()`, the current one gold and the rest `goldDeep`, the viewport following the current one. Alt+↑/↓ put your message before or after the viewport's top at the top, with Shift a tool call or command; the message box ignores Alt+↑/↓ in full screen. Ctrl+F and these aren't keybindings.json actions, since Claude Code has none for them.
- Edits are diffs from `editLines()`: Claude Code's `structuredPatch` when it sent one, with line numbers, else `diffLines()` of `old_string` and `new_string` (a line LCS, given up past 1,000 lines a side). The permission prompt diffs the same way, without a panel of its own (`framed={false}`). Each side is highlighted as one text in the file's language and read back into cells (`cellsOf()`), so styles carry across lines; a removed run is paired with its added run by likeness (`align()`, character-pair Dice, 0.4 or more), and each pair compared word by word, the changed words on `TINT.removedWords`/`addedWords`, with a space between two changed words tinted too, unless they share under 35%. `paint()` spells out every cell's whole style, background included, since a tint inside a row can't lean on the row's. Long lines wrap, at a space in the row's second half when there is one, later rows indented as far as the line's text (past a comment's leader such as `/** ` or `// `, at most half the row), the line number on the first row only. At `SPLIT_WIDTH` (140 cells) and wider, the old side goes left and the new right.
- In full screen a code block's panel has `copy` on its top edge: a link to `astrocode:copy:<hash>` (`copyLink()`), the text kept in `links.ts`, which `openAddress()` copies instead of opening. Only full screen's transcript passes `copyable`, since in scrollback the terminal would try to open it. The other way round, the file a tool row acts on is a `file://host/path` link only in scrollback (`scrollback` on `ItemView`), where the terminal opens it; in full screen a click on the row opens the row.
- Once a turn has ended, a run of three or more tool calls that went as planned folds into one row (`folds()` in `src/view/folds.ts`): how many, of what kinds, how long, and under it a line per call, `$ command` or the tool and its target, at most eight. Calls that show you something (edits, writes, answers, to-dos, pictures), that failed, were refused or stopped, or went to the background end a run. In full screen a click unfolds it, the calls following under its row, and Ctrl+O on a folded call opens its fold too. Scrollback folds only replayed turns, since `<Static>` has already written a live turn's calls by the time it ends. The fold's key is its own (`fold:` and its first call's key); a closed fold's calls have no rows, so no `starts`.
- A turn's closer counts the files its edits and writes changed and the commands Claude ran (`turnWork()` in the reducer, at the turn's end; a replayed turn counts them in `closeTurns()`). In full screen it opens like a tool call, to list them.
- The mouse is on only in full screen. In scrollback it would take the wheel from the terminal's own scrollback. `Mouse` lifts SGR reports out of `stdin.read()` before Ink parses input, and turns reporting off on exit, crash included. It reports plain movement too (1003) for `useHover`: what a click would act on gets `PALETTE.hover` under the pointer, and the pointer's shape is set with OSC 22, by the cell under it: a hand where a click acts, a text beam over text a drag selects, and the terminal's default over an empty cell. In the transcript, text is a row's words and the spaces between them (`isTextAt()`), not the rail, a panel's padding or edges, indentation, the cells after the text or a gap wider than `WORD_GAP`; while a drag selects, the beam stays. The message box is a text beam all over, since a click anywhere in it puts the cursor there. OSC 22 draws nothing, so it's written between Ink's frames, as are the mouse modes and kitty's image commands (which answer nothing, with `q=2`); `stop()` puts the default shape back.
- A component finds what was clicked with `hit()` on a Box ref, and sets `event.handled` on events it uses. The viewport listens as a fallback, so the wheel scrolls the transcript unless a picker or menu under the pointer used it. Clicks on the permission and question prompts wait for `GRACE_MS` too.
- A `!` command opens by default once it has ended (`opensByDefault()`), its whole output under it in both layouts; Claude's calls start closed. One still running shows its live tail, and in scrollback one that went to the background while running stays closed, since `<Static>` would keep half its output. Full screen's `expanded` set holds the entries a click turned away from how they start.
- In full screen a click on any row of a tool call or a `!` command opens or closes it in place (`Row.hot`), so a long output closes from wherever you've scrolled to. Inside an opened one, a click on text waits out a double click (`MULTI_CLICK_MS`, 300 ms) before it closes, since a double or triple click there copies a word or a line, and a click on a blank cell (`isTextAt()`) closes it at once; and the entry's first row then takes the clicked row's place on screen. A drag selects, as anywhere. What's open is text to select, and only its first row gets the hand and the hover band; a closed one bands all its rows. A command still running, or Claude's that went to the background, opens its task view instead. Rows on a panel are raised a step on hover rather than banded, so the panel still shows.
- Links go to the terminal as OSC 8 hyperlinks (`hyperlink()` in `tui/links.ts`), ended with BEL, since Ink's wrapping carries a link onto its next line only then: Markdown links and bare web addresses, which `spans()` gives an `href`, and web addresses in tool and command output (`linked()`), not in code. Only http and https become links. In scrollback the terminal opens them itself. In full screen `linkAt()` reads the address under a cell from the drawn line, the pointer is a hand over it, its cells get the hover band, and a click opens it with `xdg-open` (`open` on macOS) once it's plain it isn't a double click, which copies the word instead. A link wins over the tool call it's in.
- A question's preview follows the pointer, else the chosen option, and is always as tall as the tallest of the question's previews: the prompt is pinned to the bottom in full screen, and a taller preview would push another option under a pointer that held still.
- A selection starts once a drag leaves the cell the button went down on, so a click highlights nothing. It copies what's highlighted, no more: `cellsOn()` decides both. It leaves out the rail's gutter (`Row.inset`), a panel's padding and edges, and a quote's hairline.
- astrocode's look is its own. Colors come from `PALETTE` in `tui/theme.ts`, never terminal color names or hex values elsewhere: gold is the user (their messages, what waits on them, focus, selection), teal is Claude, rose is failure, ember is stopped or denied. Gold appears only where the user is or is needed.
- The quiet colors are made from the terminal's own theme. `cli.ts` asks the terminal for its background and text colors (OSC 11 and 10, then DA1, which every terminal answers last, so one that ignores the color questions costs no wait) before it imports the interface, since the palette and everything built from it at load (`TINT`, `PANELS`, the tone tables) is made once, as `theme.ts` loads. Panels are the background moved toward the text color to a set contrast (1.2:1, raised 1.5:1), so they're a step off any background, light or near-black; secondary text and lines are mixes of the two, held to 4.5:1 and 3:1. The accents keep their hues and move only as far as it takes to read at 3:1, which on a light background darkens them. A terminal that doesn't answer gets the dark palette exactly as it was. tmux answers for its pane from `window-style`, which makes a light theme testable there; kitty on Xvfb (`-o background=… -o foreground=…`) shows it. A theme changed while astrocode runs takes effect at its next start.
- Every transcript entry draws its own piece of the rail through `Railed`, with its place from `rails()`. Spacing between entries is the rail's gap row, not margins, so the rail stays continuous in `<Static>` and in full screen alike. A turn closes with a `turn` item; a replayed conversation gets its closers from `closeTurns()`.
- Shell commands, Claude's Bash calls and your `!` commands alike, are cards (`shell-card.tsx`) drawn from a `Run` (`runOfCall()`, `runOfShell()`): the headline is Claude's `description` for the call, or your command, with how it went at the right; under it, on a band of the panel color, `$ command` and the one line that says the most (`runInsight()`: Claude Code's `gitOperation` or `returnCodeInterpretation`, a line of totals such as a test run's, else the last line printed), and a failure's last error lines. A failed Bash result's text starts with `Exit code N`. Opened (Ctrl+O, a click in full screen, or a `!` command that ended), the band holds the whole command and then the whole output in place of the summary line, one surface with no panel edges between; past 2,000 lines a last line says how many more. Times come from the `at` events carry, set as they arrive, or in a replay from the `timestamp` Claude Code saves with each message, which `getSessionMessages()` returns but the SDK's types leave out. A replayed turn is timed from your message to the last thing saved in it, with no tokens. A saved conversation has no structured results, so a replayed command that went to the background is known only by Claude Code's "Command running in background with ID:" note.
- Code and anything a tool printed go on a `Panel`; prose doesn't. Text colored by a tool or highlighter goes through `onPanel()` first, so its resets don't punch holes in the panel. A panel with the user's keys gets `accent` (the gold hairline). `selection.ts` recognizes panel rows by their background, so a new panel background must be added to `PANELS` there.
- `tui/markdown.ts` (the Markdown parser) began as a copy of nebula-ui's and is astrocode's own now; nebula is going away, so there's nothing to port to. Links keep their URL as a `url` span, and inline code, links and emphasis nest inside bold, italic, strike and link text. Claude's strong emphasis is teal, since bold alone barely shows. Your messages go through the same `Markdown` with `voice="you"`: bold and bright, strong emphasis in gold, indentation kept. Thinking goes through it with `voice="thinking"`, quiet italic gray. Asterisks and underscores must hug what they emphasize, and underscores, single or double, never open or close inside a word, so `*.ts`, `snake_case` and `mcp__server__tool` stay as typed. One name between double underscores is a Python dunder (`__init__.py`, `__name__`), not bold, unlike CommonMark; `[Image #n]` is its own span. A run of blank lines is one paragraph break, however many were typed. A fence indented under a list item is a code block of its own, indented as far as the fence (at most half the width), and a prose line indented two or more keeps its indent on every row, so a list item goes on past its code.
- Auth comes from the user's Claude Code login, which is their subscription. Never add API-key handling, and never read credentials in astrocode. `topLevelEnv()` removes only Claude Code's session markers from the environment; settings pass through.
- Testing spends the user's plan. Use `ASTROCODE_MODEL=haiku` and a throwaway project folder, never this repo or another real project.
  - Drive the app in tmux on its own socket (`tmux -L <name>`, `send-keys`, `capture-pane -p`). Send typed text and Enter in separate `send-keys` calls with a pause between them: tmux can deliver them as one chunk, and Ink then passes the Enter along with the text instead of as Enter.
  - Mouse: send SGR reports as bytes with `send-keys -H` (`ESC [ < button ; x ; y M` to press, `m` to release; 32 added to the button for a drag, 64 and 65 for the wheel; 1-based cells). `tmux display -p '#{mouse_sgr_flag} #{alternate_on}'` shows whether reporting and the alternate screen are on. With `set -g set-clipboard on`, a copy lands in `tmux show-buffer`.
  - vhs can't send mouse events. To screenshot full screen, have vhs attach to the tmux session and drive the app from a background script.
  - tmux can't show kitty's pictures. Run kitty hidden on Xvfb (`Xvfb :97 &`, then `DISPLAY=:97 KITTY_DISABLE_WAYLAND=1 kitty --config NONE -o allow_remote_control=yes --listen-on unix:<sock> env -i … TERM=xterm-kitty bun src/cli.ts …`), type with `kitten @ --to unix:<sock> send-text` (a drop is `\x1b[200~path\x1b[201~`), and screenshot with `DISPLAY=:97 import -window root shot.png`. Windows stack there without a window manager, and one opened on top makes kitty redraw the one below, which can hide a picture that wouldn't otherwise show. To narrow down a drawing problem, record astrocode's output with `script` in tmux (`env -i … TERM=xterm-kitty`) and replay it into that kitty, pausing where astrocode would.
  - Take color screenshots with vhs: `Set Theme "Catppuccin Mocha"`, relative screenshot paths that don't start with a digit, and `/clear` between scenes, since vhs reads the top of the buffer.
  - Start with `env -i HOME=… PATH=…` so this session's own environment doesn't leak in, and with `XDG_CONFIG_HOME` and `XDG_STATE_HOME` set to throwaway folders so test picks and stashes don't land in the user's own.
  - Before quitting with Ctrl+D, make sure the box is empty (Ctrl+C first): Ctrl+D does nothing with text in the box, and whatever is typed next, such as the command to start astrocode again, goes to Claude as a message. Check the shell prompt is back before typing at it.
  - Test keybindings with `CLAUDE_CONFIG_DIR` set to a throwaway folder holding a `keybindings.json`, never the user's `~/.claude`.
  - Test a click on a link with a fake `xdg-open` early in `PATH` and `DISPLAY` set to anything, never the user's own browser.
  - Test Ctrl+V with a fake `wl-paste` early in `PATH` and `WAYLAND_DISPLAY` set to anything, never the user's own clipboard. A file drop is a bracketed paste of its path: `tmux set-buffer` then `paste-buffer -p`.
  - Plugin changes write to Claude Code's real settings and plugin folders. Test them with `CLAUDE_CONFIG_DIR` set to a throwaway folder and a local marketplace (`claude plugin validate` checks one). That run isn't signed in, but `/plugins` and `reloadPlugins()` don't need it.
