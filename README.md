# astrocode

Our own version of `claude`: Claude Code's engine with a terminal front end of our own, built on the [Claude Agent SDK](https://code.claude.com/docs/en/agent-sdk/overview).

The SDK runs the Claude Code binary, so astrocode uses the same login as `claude`, which is your Claude subscription. It also loads the same settings, CLAUDE.md files, skills, plugins, hooks and MCP servers. Only the interface is ours.

## Run it

```sh
cd ~/Projects/astrocode && bun install
alias astrocode='bun ~/Projects/astrocode/src/cli.ts'   # add to ~/.zshrc
```

Then, in any project folder:

```sh
astrocode                 # start a session here
astrocode -c              # continue the most recent session here, with its history on screen
astrocode -r <id>         # resume a session; astrocode prints the id when you exit
astrocode -m opus         # pick the model
astrocode -e high         # pick the effort
astrocode -f              # full screen, with the mouse
astrocode agents          # Claude Code's background sessions, as `claude agents` lists them
```

Sessions are saved where Claude Code saves its own, so `claude --resume <id>` opens an astrocode session too, and `/resume` in astrocode lists sessions from both.

| Shift+Tab | Change the permission mode: ask first, accept edits, plan, auto, bypass permissions |
| Alt+P | Switch the model (↑↓) and its effort (←→) in one picker |

Ctrl+Enter needs a terminal with the kitty keyboard protocol |

| `?` in an empty box | Every key, for whatever has your keys, as your `keybindings.json` binds them, and the mouse in full screen and in scrollback's transcript viewer. `?` in the transcript, in an opened call, in an opened ledger and in a permission prompt lists theirs first (a prompt's as that prompt takes them; in its comment, `?` is typed); `/help` lists the box's, with the transcript's after them, for Ctrl+O. Type to filter, ↑↓ or the wheel scroll, Esc closes and leaves what was under it as it was |
| Tab or → in an empty box | Take Claude Code's suggested next message, to send with Enter or change first. Claude Code suggests one after some turns, not all, and the empty box shows it in dim italics with `tab to use`, or `→ to use` where your keybindings.json gives Tab to something else. Typing hides it and emptying the box brings it back, as in `claude`; anything you send uses it up, a `!` command or a /command too, but for `/diff`, which only takes you to the ledger. Claude Code's own `promptSuggestionEnabled` setting and `CLAUDE_CODE_ENABLE_PROMPT_SUGGESTION` turn suggestions off; astrocode has no setting of its own |
| Ctrl+R | Search what you've sent, here and in `claude`, in every folder: type to find, Ctrl+R for older matches, Enter keeps it, Esc cancels |
| Ctrl+_ | Undo, a word at a time |
| Ctrl+K, Ctrl+U, Ctrl+W, Alt+D, Ctrl+Y | Cut to the end of the line, to its start, the word before, the word after; put back what was cut |
| Alt+B, Alt+F | Move a word back or forward |
| Ctrl+L | Redraw the screen, for one left garbled, keeping what you've typed. It works with a picker or a prompt open too |
| Ctrl+G, or Ctrl+X Ctrl+E | Write the message in `$EDITOR` |
| Ctrl+V | Attach the clipboard's image |
| Ctrl+B, or Ctrl+X Ctrl+B | Move the command or subagent Claude is waiting on to the background |
| Ctrl+X Ctrl+K | Stop everything in the background |
| Ctrl+T | Show or hide the to-do list |
| Ctrl+O | Move your keys to the transcript and back: ↑↓ move a cursor over its lines and Enter opens the line it's on in place (see [Full screen](#full-screen)). In scrollback it opens the transcript full screen, with the same cursor, keys and mouse, as `claude`'s Ctrl+O does, and going back leaves your terminal's scrollback as it was |
| Ctrl+Z | Suspend astrocode; `fg` in your shell brings it back |
| Ctrl+C | Clear the box, stop Claude, or exit when pressed twice |
| Ctrl+D | Exit when pressed twice on an empty box, as Ctrl+C does. With text, delete the character after the cursor |

Keys you change in Claude Code's `~/.claude/keybindings.json` change in astrocode too, in its `Global` and `Chat` contexts: rebind, unbind with `null`, or add chords such as `ctrl+k ctrl+s`. astrocode has these of Claude Code's actions: `app:interrupt`, `app:exit`, `app:toggleTodos`, `app:toggleTranscript`, `history:search`, `chat:submit`, `chat:sendNow`, `chat:queueSubmit`, `chat:newline`, `chat:undo`, `chat:stash`, `chat:modelPicker`, `chat:increaseEffort`, `chat:decreaseEffort`, `chat:thinkingToggle`, `chat:fastMode`, `chat:workflowKeywordToggle`, `chat:cycleMode`, `chat:externalEditor`, `chat:imagePaste`, `chat:clearInput`, `chat:killAgents` and `task:background`. The file is read as astrocode starts, and it says which actions it doesn't have. `chat:followClaude`, astrocode's own action for Alt+L until Follow Claude retired, does nothing now, and astrocode says so: opening the running call's line took its place. Esc, the arrows and the editing keys (Ctrl+A, Ctrl+K, Alt+B and the like) aren't actions in astrocode, though a binding can take their key; in Claude Code the editing keys aren't either, and Esc and ↑↓ are `chat:cancel`, `history:previous` and `history:next`.

## Commands

| Command | What it does |
| :-- | :-- |
| `/resume` | Pick a saved session from this folder (type to filter); its conversation replays on screen |
| `/model` | Switch the model and its effort, as Alt+P does (or `/model sonnet`) |
| `/effort` | Set how hard Claude thinks (or `/effort high`). `/effort ultracode` has Claude run a workflow of agents on every substantive task, for this session, where Claude Code offers it; a level turns it off |
| `/clear` | Start a new session on a clean screen |
| `/output` | Same as Ctrl+O |
| `/diff` | Review the latest turn's changes: its ledger opens with the cursor on it, in scrollback in the transcript viewer (see [What you see](#what-you-see)) |
| `/play` | Pick a command from Claude's shell code blocks (`bash`, `sh`, `zsh`, `shell`, or a `console` block's `$` lines) and run it as a `!` command: its output streams into a card, `/tasks` stops it, and Claude sees what it printed once it ends |
| `/pictures` | The conversation's pictures, as large as the screen allows, starting from the newest: ← and → flip through them, `o` opens one in your image viewer, `b` opens a mockup in your browser, `c` copies a diagram's source |
| `/plugins` | Manage plugins: turn them on or off, install, update and uninstall them, and add or remove marketplaces |
| `/config` | astrocode's settings: model, effort (ultracode past the highest level), thinking, permission mode, when the to-do list shows, full screen, plan usage, keeping the cache warm, agent progress, Remote Control and notifications. ↑↓ chooses, ←→ changes, Esc puts the changes into effect and saves them, Ctrl+C throws them away |
| `/tasks` | What runs alongside the conversation: background commands, subagents (those Claude waits on too), Monitors and workflows, and your `!` commands. Open one to watch it: a command's output, a subagent's transcript, a workflow's phases and agents. `x` stops it, and `b` moves a subagent Claude waits on to the background |
| `/fullscreen` | Switch to full screen, or back to the terminal's scrollback |
| `/help`, `/exit` | Every key, as `?` in an empty box lists them; quit |

Every other `/command` goes to Claude Code, and the menu lists them all: its built-ins, your skills, plugins and custom commands.

## Plugins

`/plugins` (or `/plugin`) has three lists; Tab or ← → moves between them, and typing filters the one you're on.

- **Installed.** Space turns a plugin on or off. Enter offers to update or uninstall it.
- **Discover.** Everything your marketplaces offer that isn't installed, most installed first. Enter installs it for you, for everyone on the project, or for you in this project only.
- **Marketplaces.** Enter shows a marketplace's plugins, updates its list, or removes it. Type `owner/repo`, a URL or a folder to add one.

The Agent SDK can't install or remove plugins, so each change runs Claude Code's own `claude plugin` command, and then the session reloads its plugins: new commands appear in the `/` menu straight away, with no restart.

## Agents

The agents view, headed Conversations, works as Claude Code's agent view (`claude agents`) does, with astrocode's own conversations in it. It lists the conversations astrocode runs and Claude Code's background sessions, the ones `claude agents` lists and `claude --bg` starts, across all your projects. ← in an empty message box opens it, and so does `astrocode agents`. Each project is a group, with the folder you're in first, and astrocode's conversations first in each. Each row has the Ledger's mark for its state, then its name, what Claude is doing or what it got done (what it asks you after a gold `asks:`, what runs in teal, what failed in rose), its pull requests, and when it last changed: `◐` working, `◇` in gold waiting on you, `✓` done, `✕` failed, `■` stopped, and `○` idle, for a conversation with nothing said in it yet or a background session only waiting for a prompt. The top line says where a new conversation starts, with its model, effort and permission mode; where they don't all fit, the model and effort go first, then the start of the folder. The line under it counts the rows, as in `1 needs you · 2 working · 3 done · 1 failed`. The conversation you opened the view from has its name in bold and says `(this one)`, Esc's hint names it, and its status bar stays under the view.

astrocode's conversations carry on while you're in the view or in another conversation, as background sessions do in Claude Code: start as many as you like, and open whichever needs you. While you're in one, `← 1 needs you` in gold in the status bar says another waits on you, for a permission or an answer: one of astrocode's, or a background session, which it reads every 10 seconds. ← in an empty box, or a click on it in full screen while the box is empty, opens the view, the click from the transcript too.

| Key | What it does |
| :-- | :-- |
| Type, then Enter | Start a new conversation in astrocode with the task as its first message, and stay in the view, so you can start another alongside it. It runs with the model, effort and permission mode the top line names, in the project of the row you've chosen, which the top line names too: choose a row in another project to start one there. In the folder you're in, it starts there |
| Type, then Ctrl+Enter | Start it and open it. Needs a terminal with the kitty keyboard protocol |
| ↑ ↓ | Choose a row, and with it the project a new conversation starts in. With a task typed, they move a project at a time, and the project's heading is what's highlighted |
| Enter or → | Open it. One of astrocode's conversations opens straight away, and ← in an empty message box comes back here while it carries on. A finished or stopped background session moves into astrocode: its Claude Code in the background stops, and astrocode picks the conversation up with its history on screen. So does one listed as needing input that's only waiting for a prompt. A background session that's working or waiting on you opens with `claude attach`, in Claude Code's own screen, since taking it over would cut it off. ← or Ctrl+Z there comes back to this view, and the session carries on |
| Space | What it was asked, what it says now, its result, its pull requests and its folder |
| Ctrl+X | Stop it. One of astrocode's conversations leaves the list, and `/resume` picks it up again. A background session stays listed as stopped: press Ctrl+X again within two seconds to delete it |
| Esc | Back to the conversation you opened the view from, or quit when there's none |
| Ctrl+C twice | Quit |

Quitting from the view moves astrocode's conversations to Claude Code's background service with `claude --bg --resume`, so they carry on in `claude agents` as sessions it started would, and astrocode says where each went. A conversation goes as it was there if it had run in the background before, and with astrocode's model, effort and mode if it hadn't. Its Claude Code here stops, so astrocode won't quit while Claude works or waits on you in one: open it, wait, or stop it with Ctrl+X. One the background service won't take, such as one in a folder Claude Code hasn't been trusted with, ends with astrocode, which prints how to resume it. Quitting from a conversation (Ctrl+C twice or `/exit`) ends that one, as `claude` does, and moves the rest.

astrocode reads the list with `claude agents --json`, and runs the `claude` on your `PATH` for everything in the view, since that's the Claude Code the background service runs. Each row's summary, result and pull requests come from Claude Code's `~/.claude/jobs/<id>/state.json`, which its docs say isn't a stable interface; without them, a row still shows its state.

## Files

Type `@` and part of a path to pick a file or folder from the project; Claude Code reads what you named when the message arrives. In a git repository the menu lists what git does, so ignored files stay out. A path with a space is written `@"like this"`.

## What you see

astrocode's look takes its colors from the Hubble palette, the gold and teal of narrowband space photographs. Gold is you: your messages, anything waiting on you, your cursor and your selection. Teal is Claude. Everything else stays quiet.

- **The rail.** Each turn is a path down the left edge. Your message starts it with a gold dot, every step Claude takes is a node on it (a teal diamond for a reply, `∴` for thinking, a hexagon for a tool call), and the turn's ledger closes it with a curve. Scan the left edge to see what happened.
- **The turn's ledger.** The line that closes a turn says what it changed: `1m 40s · 3 files +58 −3 · 7 passed 1 failed · not committed`. That's how long it took, the files it changed with the lines added and removed, how its last test run went (from the runner's own summary), and what it did with git: `committed f535656`, `pushed`, `PR #12`, or `not committed` in ember when files changed and nothing was committed. A turn you stopped reads `stopped after 41s · …`, and one that failed `failed: <why> · …`. In a git repository, the files are whatever changed in the working tree between the turn's start and its end, so edits Claude makes through Bash (a `sed`, a Python heredoc) count. At each edge astrocode records the working tree as a git tree, in an index and object store of its own in a temporary folder that it deletes when the session ends (or, if astrocode was killed, the next time it starts). Nothing in `.git` changes or is added: your index, refs and stash stay as they were, though git may touch the time on an object it already has. Clean filters, such as Git LFS's, don't run, so a changed LFS file counts as one binary file. A file over 10 MB is counted without its lines, and read only when you track it and it's the size git holds it at, to tell whether it was only touched. If recording an edge takes over 2 s, the session stops recording them, so no turn waits on it again. Edits to files git can't see, ignored or outside the repository, count from the edit tools' own diffs, and so does every edit outside git. Files under `~/.claude`, such as plans, don't count, unless your project is there. A resumed session has no record of its turns' trees, so its earlier turns count only their edits. A renamed file counts once, from where it was.
- **Reviewing a turn.** Enter on the ledger line with the transcript's cursor (Ctrl+O, in scrollback too), a click on it there, or `/diff` for the latest turn opens the ledger under its line, in scrollback in the transcript viewer. It lists each file the turn changed, with `new`, `+N −N`, `deleted`, `from <where it was>` for a rename, `binary` or `too big to diff`; then the commands it ran with how they went, the commits it made, and its tokens. Enter on a file opens its diff for the turn under it, numbered, with `⋯ N lines` for what the diff leaves out, unified at every width, as it keeps to the transcript's measure. A long one shows its first 12 lines and its last 8, with `⋯ N more lines` between, which Enter opens. The diff is git's, between the turn's edges, while the session keeps them; a resumed turn's comes from its edits, where it made any. `a` opens every file's diff, and again closes them, ← and → move between files, and Esc closes the diff the cursor is in, then the ledger. In a git repository `[` and `]` switch the ledger between this turn, what isn't committed (`git diff HEAD`, new files included) and the branch against the one it started from (`origin`'s default branch, else `main` or `master`), as `claude`'s `/diff` does. If git takes over 2 s to compare those, the ledger says it took too long, and turns go on being recorded. Outside an opened ledger, and outside git, `[` and `]` move the cursor to the ledger before or after.
- **The start screen.** Nothing is drawn large. It says astrocode's version and the Claude Code it runs on; where you are, with the branch, model, effort and mode; what came from Claude Code: the CLAUDE.md files, plugins, MCP servers and skills it loaded, and your `keybindings.json`; the three latest sessions saved in this folder, which `/resume` picks from and `astrocode -c` continues; and eight keys to start with, as you've bound them, with `?` for the rest. Each part shows once Claude Code has said it, never a guess. In scrollback the start screen is written there once, when it's all known, a moment after astrocode starts; a resumed conversation's history follows it.
- **Live replies.** Claude's replies stream in at the tip of the rail, where a dot circles while Claude works and light passes over what it's doing ("Thinking", "Writing", "Running Bash"), with the time so far and the tokens written. While Claude waits on you it goes, and the prompt in the box's place says so.
- **Panels.** Prose sits on your terminal's background; code and anything a tool printed sit on a panel, a filled surface with soft edges and its language set into the top edge. Code is highlighted in the same palette, tables have no grid, and quotes and callouts hang off a hairline.
- **Diagrams and charts.** In kitty, a diagram or chart Claude writes as a `mermaid`, `dot`, `d2` or `vega-lite` fence is drawn as a picture, in the same palette, once the fence is finished. The source is still what's saved, so `claude`, Remote Control and other terminals show the fence itself. A quiet line under the picture names its language and what you can do with it: in full screen, `enlarge` and `copy` (the source); in scrollback, `open`, which opens the picture in your image viewer. A diagram that can't be drawn shows its source and says why. astrocode draws with the Chromium on your `PATH` (or `ASTROCODE_BROWSER`), started when it's first needed and closed after five minutes unused; `d2` fences need `d2` installed.
- **Pictures Claude shows you.** In kitty, Claude has a `show` tool that draws a picture under its row: a screenshot of a UI it built, an HTML or SVG mockup of a design it proposes, a chart of results it measured, or up to four of them side by side under their labels, as for a before and after. Each picture is as wide as it needs, and the line under it offers `enlarge` (full screen) or `open` (scrollback), and `browser` for a mockup, which opens the page in your browser, still cut off from the network. The tool's result is the same pictures, so Claude sees what you see. Showing a picture changes nothing, so it never asks permission. Claude's system prompt says what astrocode can draw, and to draw only where a picture says it better than prose.
- **Steps.** Claude's tool calls are gathered into steps, each an activity log. A step is named by the sentence Claude wrote before its calls ("Made retry use the injected clock"); without one, its name is made from the calls and shown in italics, and the time it took is against the right edge. Under the name, a line for each thing Claude did says what it did, what it acted on, and what came of it: `Searched  Date.now in src  3 matches in 2 files`, `Edited  src/retry.ts  +9 −4 ■■■■□`, `Ran  the test suite  ✕ exit 1 · 47 passed, 1 failed`. Under 100 columns, a result that doesn't fit beside its line goes on the row under it, where the target starts, rather than cut the target short; wider, the target is cut. The verb's tense says where the call is: `Reading  src/retry.ts` while it runs, `Edit  src/cache.ts  +1 −1` in gold as a request while it waits for your OK, `Read  src/retry.ts  47 lines` once done, `Not run  Edit src/cache.ts  you said no` (or who did, such as `denied by a rule`) when it never ran, and `Stopped  running the test suite  after 12s` when Esc stopped it. A new file reads `Wrote  src/clock.ts  new +11`. A command says what Claude said it does, in the same tense (`Running  the test suite`, `Committed  the retry change`), and the opened call shows the command itself. A command Claude didn't describe shows as `$ bun test`. Reads in a row are one line, and so are edits to one file in a row; a run of lines with the same verb writes it once. A command shows its test counts, taken only from a test runner's own summary (bun, jest, vitest, pytest, cargo, go), what Claude Code made of it (a commit, a push), or the one short line it printed, and never how many lines it printed. A failure says why on the line under it: the assertion that failed (`Expected: 3, Received: 4`, `assert 4 == 3`), else the error's own message, never a line of source; a running subagent shows its latest call under its line, and pictures a call returned are drawn under it. The step's mark says how it went: a teal check once done, a dot while Claude works in it, gold while it waits for you, a rose cross when its last call failed; a running line's verb is teal, the one waiting for you is gold, and `Not run` and `Stopped` are ember. A step shows six lines at most, its first two and its last three, with a line for the rest; opened, it shows every line and Claude's thinking between them. Prose that isn't a step's name, such as an explanation or Claude's reply, stays whole between steps. Pictures, plans and questions stand apart from steps.
- **An opened call.** Everything about one tool call. It opens under the call's own line in the transcript, in full screen and in scrollback's transcript viewer alike, at every width, so nothing ever stands beside the transcript: its header says what the call did, how it went (`✓ exit 0`, `✕ exit 1`, or a gold `◇` while it waits for you, which the prompt says), how long it took, and which of the turn's calls it is (`‹ 2 of 10 ›`). Its tabs depend on the tool: a command has Output (what it printed, numbered, with what it printed as errors after it), Command (the whole command, its description, timeout, background, exit code and times), Sent to Claude (the result exactly as Claude got it) and Input (the call's input as JSON); an edit has its diff, a read the file as Claude saw it, a subagent its calls, its prompt and its report, a search its results, a fetch its response. A command that waits for your OK opens on Command, since it has no output yet; once it runs, in the background too, Output shows what it has printed so far, read again each second. A line of several calls opens the one waiting for your OK, else the one still running, else the first. A long tab shows its first 12 and last 8 lines, with `⋯ N lines` between, which opens the rest. The call's line stays gold while it's open. Open the line of a call Claude is on, running or waiting for your OK, and it follows Claude: each call Claude starts after it opens under its own line as it starts, and the one before closes, until you move the cursor or scroll away, while the view goes on following the end. A call that waits for your OK opens once you've answered, so its prompt sits right under its line until then.
- **Tool calls on their own.** A call that stands apart from steps, such as a picture Claude shows you or a question, has a row of its own with a hexagon that says how it went: filled teal once it's done, rose if it failed, an outline while it runs or after it was stopped or denied, gold while it waits for you. Its row names the tool and what it acts on, with the result against the right edge, and keeps what matters: the pictures, the to-do list, or your answers to Claude's questions.
- **Permission prompts.** A prompt takes the message box's place, right under the line that asks, until you answer; what you'd typed in the box is still there after. Its words and choices are `claude`'s, tool by tool: `Bash command` and `Do you want to proceed?` with Yes, `Yes, and don't ask again for touch marker.txt commands in /home/you/app`, and No; `Create file` with `Yes, and switch to accept edits (auto-approve file edits and common file commands) for this session (shift+tab)`; `Fetch`; an MCP server's tool as `hello — Greet Tool: (MCP)`. It shows the command once, the diff or the file before you choose, with as much as leaves the asking line in view, and `waiting 12s` on its title row, the one place that says Claude waits. A prompt from a subagent names the subagent above it. "Don't ask again" applies only the narrowest rule Claude Code suggests, and the row names it. Tab on No opens `No, and tell Claude what to do differently`: what you type goes to Claude as the reason, and Claude carries on with it, while No alone stops the turn. Shift+Tab picks the row that names it, Esc says no, and Enter, Space and number keys pressed in the first half-second after a prompt appears are ignored, so a key you meant for something else can't approve it. A prompt Claude Code marks as risky starts on No, and its numbers only say no.
- **Claude's questions.** When Claude asks a multiple-choice question, it takes the message box's place, with how long Claude has waited on its title row, and you pick from a list with descriptions and previews (in kitty, each option's preview is a picture Claude drew in HTML, such as a mockup of that layout, and it changes as you move through the options; on a wide terminal it stands beside the options, on a narrow one under them), check several options where that's allowed, or type your own answer. This works in every mode, bypass included.
- **MCP servers' requests.** When an MCP server asks for details, you fill in its form (text, numbers, yes or no, a list of choices) in the message box's place, with how long Claude has waited on its title row; when it asks you to sign in, astrocode opens the address in your browser.
- **Plans.** Leaving plan mode asks `Ready to code?` with the plan as Claude wrote it, its diagrams drawn, and the file it's kept in. As in `claude`, Ctrl+G opens that file in your editor (`$VISUAL` or `$EDITOR`), to read the whole plan or change it; what you save is the plan shown, and the one you approve. As in `claude`, the first choice switches to bypass permissions for the rest of the session, or, where your settings turn that off, to auto mode, else to accept edits; `Yes, manually approve edits` goes back to asking first; and typing in `Tell Claude what to change`, then Enter, keeps Claude planning with what you said.
- **Keywords.** `ultrathink` in a message asks for deeper reasoning that turn, and `ultracode` for a workflow of agents. Claude Code acts on them; astrocode draws them through the palette's accents in the box and in your message, and the box says what each will do.
- **Background work.** A command, subagent, Monitor or workflow that runs in the background says so on its line, a notice says when it ends, and when Claude picks up where it left off by itself, as on a Monitor's event, a line says why. Its line opens a command's output as it prints and a subagent's calls under it, and a Monitor's or workflow's view in `/tasks`. Esc stops Claude's turn but not the work in the background; `/tasks`, or `x` on its line in the transcript, stops one thing, Ctrl+X Ctrl+K everything.
- **Subagents.** While a subagent runs, its line names its kind and counts its tool calls, and the line under it shows its latest call, in gold while that call waits for your OK. A subagent it starts goes under it, indented, with its own count and latest call. A subagent Claude waits on counts as running in the status bar and is listed in `/tasks`. A click on its line, or Enter on it, opens it under the line: Calls, what it has said and done, word for word as Claude Code sends it, streaming in as it works; Prompt, what Claude asked of it; and once it's done, Report. `/tasks` shows it with the screen to itself.
- **Where your keys go.** Always to one place: the message box, the transcript (in scrollback, its viewer), a picker or panel, or a prompt that asks you something, which takes them from the others until you answer. The box, a picker or a prompt that has your keys has a gold hairline along its top edge; the transcript has a gold `›` on the line its cursor is on, and the box's top edge lists its keys, so nothing moves as it takes them. While it has your keys its cursor stays in view: scrolling away brings the cursor along.
- **Width.** The transcript is one column: its text never runs wider than 110 columns, however wide the terminal, so a result stays near the line it's for, and what opens under a line keeps to it too. It stops two columns short of a narrower terminal's right edge. The box, the status bar and a prompt in the box's place take the whole width, so a diff in a permission prompt goes side by side on a wide terminal.
- **The status bar.** The permission mode as a solid chip, and while other conversations wait on you, how many in gold, as in `← 1 needs you` (see [Agents](#agents)); then readings: `◌ N running` while something runs alongside the conversation, how full the context is (`context 18%`, ember and then rose as it fills), your plan's 5-hour and 7-day usage (with reset times once they get high), the model and the effort you set (`Opus 5.5 xhigh`, or `ultracode` in the effort's place), and the git branch and changed files (`main ±3`). As the terminal narrows they drop by rank, the branch first, then the model and effort, the 5-hour usage, what's running and the 7-day usage, so the context goes last; the mode and the count always stay. After them, as room allows, come the prompt cache's time, `↯ fast` in fast mode, `thinking off`, `⇄ remote` and your plan. While a request is being tried again, or the conversation compacted, the line above the box says so.
- **Scrollback.** Finished output goes into your terminal's own scrollback, like `claude`. A step goes there once Claude has moved on from it, closed, with its lines. Ctrl+O opens the transcript viewer, as in `claude`: the whole conversation full screen, with full screen's cursor, keys and mouse (see [Full screen](#full-screen)), so any step, call or turn's ledger opens in place. It's on the terminal's alternate screen, so Esc, `q` or Ctrl+O goes back to your scrollback as it was; what Claude finished meanwhile is written there then.

## Full screen

`astrocode -f`, `ASTROCODE_FULLSCREEN=1` or `/fullscreen` gives astrocode the whole terminal, like vim or htop. The conversation, under the start screen, is in a viewport of its own, with the message box and status bar pinned under it. It starts at the top while it fits, and once it doesn't, it follows the end; while a prompt waits on you, its end sits right above the prompt. Before your first message, a start screen taller than the screen shows its top, and scrolls to the rest. The mouse works:

| Do this | And |
| :-- | :-- |
| Scroll the wheel, or PgUp and PgDn | The conversation scrolls. Scroll up and it stays put while Claude writes, and a call opened on Claude stops following it; the pill at the bottom says how much is below. Click it, or press Ctrl+End, to follow again. Ctrl+Home goes to the top |
| Drag | Selects text and copies it when you let go, through the terminal (OSC 52) and the desktop clipboard. It copies only content: not the rail, and on a panel only the code, without its padding or edges |
| Double-click, triple-click | Copies a word (or a path or URL), or a line |
| Ctrl+O | Moves your keys to the transcript, with a cursor on the last line in view: ↑↓ move it, a line at a time, over what's opened too, and Enter does what a click on the line does. PgUp and PgDn move it half a screen, Home and End to the first line and the last (End follows the end again), and `{` `}` or Alt+↑ Alt+↓ to your message before or after, Alt+Shift+↑ Alt+Shift+↓ to a tool call. `x` stops the subagent or command on the cursor's line while it runs, one in the background or one of yours too. In an opened call ← and → open the call before or after, Tab its next tab, `c` copies the tab and `e` opens it in `$EDITOR`. In an opened ledger ← and → move between its files, `a` opens every file's diff, and in git `[` `]` switch its scope; elsewhere `[` `]` move to the ledger before or after. As in `claude`'s transcript viewer, `/` finds: Enter keeps the match, with the cursor on it, and Esc goes back to where you were; `n` and `N` then go on to the next and previous line with a match, round past the ends; and `v` opens the whole conversation in `$EDITOR`. Ctrl+F finds too, from the box as well, Enter or ↑ going to the match before and ↓ to the one after. Esc closes what's open, then gives your keys back to the box; Ctrl+O and `q` give them back at once, as does a click on the box. The keys that work anywhere still do: Ctrl+C stops Claude, Shift+Tab changes the mode, Shift+↑↓ the effort, Ctrl+L redraws the screen, and so on. None of them touches what's typed in the box: Ctrl+C there stops Claude, or exits on a second press, without clearing it, and Ctrl+D exits on a second press only with the box empty |
| Click a line | Puts the cursor there, with your keys, and does what Enter does |
| Click a line in a step | Opens that call under the line, at every width; a click on the line again, or on what opened, closes it. A click on another line opens that one instead. A running subagent opens there too, its calls streaming in, and so does a command, in the background too, with what it has printed so far. A Monitor or a workflow opens its view in `/tasks` |
| Click a step's name | Opens the step, with every line and Claude's thinking between them; click again to close it |
| Click a call on its own, such as a picture's or a question's row | Opens it under its row, as a line in a step does |
| Click a tab, `‹` or `›`, or `⋯ N lines` in an opened call | Shows that tab, opens the call before or after, or shows the whole tab |
| Click a turn's ledger line, a file in it, or a scope's tab | Opens the ledger under its line, that file's diff under the file, or that scope's files |
| Click `▶ run` on a shell code block | Runs it as `/play` does. `copy` beside it copies it |
| Click a picture | Enlarges it, as `/pictures` does; ← and → flip to the pictures before and after it. A click on the enlarged picture, or on `esc close` under it, puts it back |
| Click an option | Chooses it, in permission prompts, Claude's questions, pickers, `/plugins`, and the `/` and `@` menus |
| Click the mode, the model or the effort | Changes the permission mode, or opens the model or effort picker |
| Click `← 1 needs you` in the status bar | Opens the agents view whenever the message box is empty, also while the transcript has your keys. With something typed in the box it waits, so nothing you've typed is lost |
| Click in the message box | Puts the cursor there |
| Drag the scrollbar | Scrolls |
| Hold Shift | Uses the terminal's own selection instead |

What a click acts on lights up under the pointer: a step's line, a card's title or a link turns gold, with nothing drawn behind it, and the pointer becomes a hand, or a magnifying glass over a picture, which a click enlarges or puts back. Over text the pointer stays an arrow, though a drag still selects it. The line of the call that's open stays gold, with a gold mark.

Full screen uses the terminal's alternate screen, so the conversation isn't in your scrollback when you leave. `/fullscreen` switches back and writes it there.

## Settings

`/config`, and the model, effort, thinking, mode and layout you pick anywhere else, are kept for next time in `~/.config/astrocode/settings.json` (under `$XDG_CONFIG_HOME` if it's set), not in Claude Code's settings, so `claude` keeps its own. Plan mode, max effort, ultracode and fast mode are for one session only, as in Claude Code. A stashed message is kept per project in `~/.local/state/astrocode/stash/` (under `$XDG_STATE_HOME` if it's set), with its images. What you send, and what Esc twice clears from the box, goes into Claude Code's prompt history, `~/.claude/history.jsonl` (under `$CLAUDE_CONFIG_DIR` if it's set), in its format, so ↑ and Ctrl+R go through the same messages in `claude` and in astrocode; astrocode keeps no history of its own. `CLAUDE_CODE_SKIP_PROMPT_HISTORY=1` keeps what you send out of the file, as it does for `claude`. So does an API key, a token or a credential in a message, by `claude`'s own patterns: `claude` checks `!` and `/` commands and pasted text, and astrocode, which puts what you paste in the message itself, checks the whole message. Such a message stays on ↑ until you quit.

| Variable | Default | What it does |
| :-- | :-- | :-- |
| `ASTROCODE_ACCENT` | gold | Your color, as a hex color such as `#F0B85A` |
| `ASTROCODE_MODEL` | Claude Code's default | The model, as with `-m` |
| `ASTROCODE_EFFORT` | Claude Code's default | The effort, as with `-e` |
| `ASTROCODE_FULLSCREEN` | off | `1` starts in full screen, as with `-f` |
| `ASTROCODE_BROWSER` | the first Chromium on your `PATH` | The browser astrocode draws diagrams and charts with |

astrocode is designed for a dark theme with true color, such as kitty. Its colors are its own, so it looks the same whatever theme your terminal uses.

## Signing in

astrocode uses whatever Claude Code is signed in with; the status bar shows the account, for example "Claude Max". Keep `ANTHROPIC_API_KEY` unset. If it's set, Claude Code uses the key, and that usage is billed to the key instead of your subscription.

Keep it for your own use. Anthropic's [terms for Claude Code](https://code.claude.com/docs/en/legal-and-compliance) don't allow offering subscription sign-in in an app other people use.

## How it fits together

- `src/cli.ts` is the `astrocode` command.
- `src/session.ts` runs one Claude Code session through the Agent SDK in streaming-input mode. It turns permission checks and Claude's questions into prompts, and reports the account, the models, the commands and context usage.
- `src/events.ts` defines what the session tells the interface.
- `src/history.ts` lists saved sessions and loads a saved conversation.
- `src/prompt-history.ts` reads and adds to Claude Code's prompt history, for ↑ and Ctrl+R in the message box, under Claude Code's lock on it. It leaves out messages `src/secrets.ts`, Claude Code's own test for secrets, finds one in.
- `src/plugins.ts` lists and changes plugins and marketplaces through `claude plugin`, with the Claude Code binary the SDK ships.
- `src/agents.ts` lists Claude Code's background sessions and stops, deletes and hands conversations to them, through the `claude` on your `PATH`. `tui/agents.tsx` is the agents view, `tui/fleet.ts` holds the conversations astrocode runs at once, and `tui/main.tsx` switches between the view and a conversation.
- `src/canvas.ts` draws diagrams, charts, SVG and HTML as pictures, with a headless Chromium that reaches neither the network nor the disk.
- `src/snapshots.ts` records the working tree at each edge of a turn as a git tree, and diffs the two for the turn's ledger, a file at a time for its review, and against HEAD or the branch's base for `/diff`'s other scopes. `src/view/patch.ts` reads a diff into numbered lines.
- `src/view/` holds the reducer that turns events into what's on screen (live and replayed alike), plus tool summaries, permission wording and formatting. `src/view/steps.ts` gathers tool calls into steps, `src/view/activity.ts` turns a step's calls into its activity lines, and `src/view/ledger.ts` reads what a turn did into the line that closes it.
- `tui/` is the Ink front end. `tui/theme.ts` holds the palette, `tui/rail.tsx` the rail, and `tui/markdown-view.tsx` the panels and Markdown drawing; `tui/markdown.ts` is the Markdown parser. `tui/plugins.tsx` is `/plugins`, and `tui/files.ts` finds files for `@`. `tui/screen.tsx` is full screen, and scrollback's transcript viewer (`tui/viewer.ts`): `tui/transcript.tsx` draws the conversation as lines, each line of a step knowing which call it stands for, `tui/mouse.ts` reads the mouse, and `tui/selection.ts` and `tui/clipboard.ts` copy. `tui/entries.tsx` draws steps and the other entries, `tui/opened.tsx` a call opened under its line, and `tui/inspector.tsx` the tabs it shows. `tui/ledger.tsx` draws a turn's ledger opened, and `tui/review.ts` reads what it shows.
